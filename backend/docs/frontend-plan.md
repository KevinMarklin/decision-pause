# План: MAX Mini App (фронтенд)

Контракт API: [`docs/api.md`](api.md). Вопросы по бэкенду — разработчику бэкенда.

---

## 1. Стек и настройка

- **Vite + React + TypeScript** (Tailwind/CSS Modules — на выбор)
- Папка: `frontend/` в корне репозитория (рядом с `backend/`)
- Dev-proxy в `vite.config.ts` (CORS не нужен):

```ts
server: { proxy: { '/api': 'http://localhost:8080' } }
```

- MAX Bridge — в `index.html`:
```html
<script src="https://st.max.ru/js/max-web-app.js"></script>
```
- Работаем в браузере (npm run dev) — MAX нужен только для финальной проверки.

## 2. Пользовательский путь (критерий готовности)

```
Bot → «Начать анализ» → выбор «Взять кредит» → анкета (9 полей)
→ экран проверки [Изменить][Рассчитать] → POST → 3 сценария
→ «Последствия» → чек-лист → «Завершить анализ»
```

Все шаги обязаны работать от начала до конца — UI потом.

## 3. Экраны

| # | Экран | Содержание |
|---|---|---|
| 1 | Home | Заголовок «🧠 Анти-импульс», дисклеймер «Мы не принимаем решение за вас», карточка **💳 Взять кредит на развитие** → переход к анкете |
| 2 | Анкета | 9 полей (см. ниже), клиентская валидация по тем же правилам, что в `api.md` |
| 3 | Проверка | Список введённых данных, кнопки **[Изменить] [Рассчитать]** |
| 4 | Результат | Блок «Кредит» (платёж, выплаты, переплата) + 3 карточки сценариев (🟢🟡🔴): выручка, расходы, платёж, **свободный поток**, нагрузка %, резерв. Кнопка **[Посмотреть последствия]** |
| 5 | Последствия | По выбранному сценарию: массив `consequences` (тексты готовы, не перефразировать) |
| 6 | Чек-лист | 5 пунктов из `checklist` с чекбоксами, кнопка **[Завершить анализ]** → Home |
| 7 | История | `GET /api/decisions` — дата, сумма, платёж, 3 cash_flow |

Поля анкеты (тип number, кроме `purpose` — text):

```
loan_amount, loan_term_months, interest_rate_pct,
revenue, expenses, reserve,
revenue_growth_pct, expense_growth_pct, purpose
```

## 4. Работа с API

- `POST /api/decisions` → ответ **одним запросом** содержит credit + scenarios + checklist
- Идентичность пользователя:
  - **прод:** заголовок `X-Max-Init-Data` со **сырой строкой**
    `window.WebApp.initData` (не `initDataUnsafe`!) — бэкенд проверит подпись;
    без неё придёт `401 {"error":"unauthorized"}`;
  - **dev:** `X-Max-User-Id: window.WebApp?.initDataUnsafe?.user?.id`
    (в браузере undefined — просто не шлём; битое значение → `400 invalid_user_id`).
- Ошибка `400 {error:"validation", fields:{...}}` → подсветить поля сообщениями
- `400 {error:"unknown_field", field:"..."}` → опечатка в имени поля формы,
  показать как обычную ошибку валидации
- `401 {error:"unauthorized"}` → «Откройте приложение заново» (протухлая подпись)
- Остальные ошибки: экран «Что-то пошло не так, попробуйте ещё раз» + повтор
- Loading-состояние на кнопке «Рассчитать» (запрос быстрый, < 100 мс)

## 5. MAX-специфика

- `window.WebApp.ready()` при монтировании
- Опционально (если успеваем): «Удалить анализ» → `DELETE /api/decisions/{id}` →
  `204`; `404` — уже удалён или чужой
- Всё рендерим под ширину MAX (375px+, тёмная/светлая тема — если время)
- initData **не валидируем** на фронте (это делает backend-команда при необходимости)
- Deep link мини-аппа: `https://max.ru/<bot>?startapp=...` — payload не используем

## 6. План по дням и коммиты

Коммиты на английском, префикс `feat(frontend): ...` / `chore(frontend): ...`.

| День | Задачи | Коммиты |
|---|---|---|
| 1 | Vite+React+TS каркас, роутинг экранов (заглушки), proxy, MAX Bridge | `chore(frontend): scaffold Vite + React + TS`, `feat(frontend): add screen routing and home` |
| 2 | Анкета: 9 полей, валидация, переход на «Проверка» | `feat(frontend): add loan form with validation`, `feat(frontend): add review screen` |
| 3 | Результат: вызов API, 3 карточки сценариев, блок кредита | `feat(frontend): call API and show three scenarios` |
| 4 | Последствия + чек-лист + история + заголовок X-Max-User-Id | `feat(frontend): add consequences and checklist`, `feat(frontend): add history` |
| 5 | Полировка, адаптив, прогон всего пути в MAX | `style(frontend): adapt UI for MAX`, баг-фикс коммиты |

**День 3 — жёсткий дедлайн:** путь «анкета → расчёт → 3 сценария» должен работать.

## 7. Не делать (до защиты)

❌ собственную бизнес-логику расчётов — **все цифры приходят с бэкенда**;
❌ авторизацию; ❌ второй язык; ❌ анимации без времени; ❌ больше одного типа решения;
❌ парсить/форматировать тексты `consequences` (готовы на русском).

## 8. Проверка готовности

1. `npm run dev` → полный путь в браузере на данных из `docs/api.md`
2. История показывает созданный анализ
3. Валидация подсвечивает все 8 полей
4. В MAX: бот → кнопка → приложение открывается → путь повторяется
