# DecisionPause / «Анти-импульс»

Сервис, который помогает предпринимателям и руководителям **не принимать импульсивных финансовых решений**.
Первый реализованный сценарий — «Взять кредит на развитие бизнеса»: анкета → расчёт аннуитета → три сценария развития событий (ожидаемый / умеренно негативный / негативный) → тексты последствий → чек-лист рисков. Продукт **не говорит «делай/не делай»** — он объективно показывает, к чему приведёт решение.

Форма выпуска: бот в мессенджере **MAX** + встроенный **Mini App**. Рассчитывает **только backend** (LLM в MVP сознательно не используется для обеспечения 100% точности расчётов).

---

## 1. Назначение решения и основной пользовательский сценарий

### Назначение
Снятие эмоционального фактора при принятии ключевых финансовых решений (взятие кредитов, расширение штата, запуск непросчитанных маркетинговых кампаний).

### Основной сценарий использования
1. Пользователь находит бота в мессенджере **MAX** и отправляет команду `/start`.
2. Бот отправляет приветственное сообщение с кнопкой `▶️ Начать анализ` для запуска **Mini App**.
3. В интерфейсе Mini App пользователь заполняет вводные данные:
   * Сумма кредита, ставка (%), срок (в месяцах).
   * Текущие ежемесячные показатели: выручка, расходы, финансовый резерв («подушка»).
4. Система рассчитывает график выплат, анализирует кассовые разрывы и моделирует 3 сценария (базовый, -10% к выручке, -30% к выручке).
5. Пользователь получает наглядный вердикт: ежемесячный платёж, долговую нагрузку, запас прочности подушки безопасности и персональный чек-лист рисков.

## 2. Состав и архитектура решения

Решение построено по микросервисной архитектуре и упаковано в контейнеры:

* **MAX Bot Handler (Go)** — модуль взаимодействия с API мессенджера MAX через long-polling.
* **Backend REST API & Calculator (Go)** — модуль бизнес-логики и математических расчетов (аннуитеты, стресс-тесты, кассовые разрывы).
* **Database (PostgreSQL 16)** — хранение сессий пользователей, сохраненных расчетов и логов.
* **Frontend Mini App (React + Vite + TypeScript)** — клиентский интерфейс, который собирается в статический бандл и раздается напрямую бэкендом.

---

## 3. Внешние сервисы и интеграции

* **MAX Messenger Bot API** — отправка сообщений, обработка команд, генерация веб-апп кнопок (`open_app`).
* **Корневые SSL-сертификаты Минцифры (Russian Trusted Root CA)** — вшиты в контейнер приложения для гарантированного безопасного соединения с серверами MAX.
* **ИИ-модели** — в MVP-версии **не используются**. Все расчёты являются строго детерминированными и выполняются математическим движком Go.

## 5. Необходимые параметры и переменные окружения

Все ключевые параметры настраиваются через файл `.env` (шаблон представлен в `backend/.env.example`):

| Переменная | Назначение |
|---|---|
| `PORT` | HTTP-порт сервера (по умолчанию `8080`) |
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `MAX_BOT_TOKEN` | Авторизационный токен бота в MAX (если пустой — бот выключен) |
| `MAX_REQUIRE_INIT_DATA` | `true` → включение HMAC-проверки подписи initData из MAX |
| `CORS_ORIGINS` | Разрешенные домены (allowlist) для Mini App |
| `MAX_MINI_APP_NAME` | Название Mini App в мессенджере |
| `MAX_MINI_APP_URL` | Deeplink на веб-приложение |
| `FRONTEND_DIST` | Путь к директории со скомпилированной статикой Mini App |
| `TEST_DATABASE_URL` | Строка подключения для запускa интеграционных тестов БД |

## 6. Файлы Docker и конфигурации

В репозитории присутствуют все необходимые конфигурационные файлы для развертывания и разработки:

* **`docker-compose.yml`** — конфигурация оркестрации сервисов (`app` и `postgres`).
* **`backend/Dockerfile`** — мультистадийный (multi-stage) файл сборки образа (Stage 1: Frontend Node.js, Stage 2: Go Builder, Stage 3: Alpine Runner).
* **`.dockerignore`** — список исключений для оптимизации сборки Docker.
* **`backend/.env.example`** — шаблон конфигурации окружения без реальных секретов.
* **Файлы зависимостей:**
  * Backend: `backend/go.mod`, `backend/go.sum`
  * Frontend: `frontend/package.json`, `frontend/package-lock.json`

9. Примеры ожидаемого поведения системы и известные ограничения
Ожидаемое поведение
При превышении долговой нагрузки > 50% от чистой прибыли система выделяет показатели красным цветом и выводит предупреждающий блок рисков.

При отрицательном Cash Flow в негативном сценарии автоматически рассчитывается число месяцев до полного исчерпания резерва.

Известные ограничения (MVP)
Расчёт поддерживается только для кредитов с аннуитетными платежами (дифференцированные платежи не включены в текущий релиз).

Валюта расчёта — исключительно рубли (₽).

Расчёты производятся в текущих ценах без динамического моделирования инфляционных колебаний.
